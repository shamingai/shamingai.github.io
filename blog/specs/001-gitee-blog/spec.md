# Feature Specification: Gitee 博客

**Feature Branch**: `001-gitee-blog`

**Created**: 2026-10-12

**Status**: Draft

**Input**: User description: "需要开发一个 gitee 博客，前后端分离，使用 git 上传下载"

## Clarifications

### Session 2026-10-12

- Q: 作者的 Git 仓库是由这个网站提供，还是作者自己已有的 Gitee 仓库？ → A: 作者使用自己的 Gitee 仓库。网站只展示该仓库的内容，不接收 Git 推送，也不提供仓库的上传和下载。

### Session 2026-10-13

- Q: 这个网站是只展示你这一位作者的博客，还是以后也要展示其他作者的博客？ → A: 只展示这一位作者的博客。网站只有一位作者、一个 Gitee 仓库。博客由作者在本地写完，再用 Git 上传到该仓库。
- Q: 网站从仓库里把哪些内容当作一篇博客？ → A: 只认作者约定为文章的内容，其他内容忽略。
- Q: 一篇文章的标题和正文如何确定？ → A: 标题是文章的标题，正文是标题之外的内容。具体写作文件格式不在本期读者需求中定义。

### Session 2026-10-14

- Q: 网站要提供哪些阅读与发现能力？ → A: 首页文章流、文章阅读、归档、层级分类、标签、站内搜索、关于与历史。归档示例为共 45 篇并分页。分类示例为「人工智能 / 深度学习」。一篇文章属于一个分类和多个标签。历史是独立的博客时间线，不是文章归档。
- Q: 内容如何发布，网站是否提供在线编辑或后台？ → A: 文章在本地写作，生成静态站点后发布。网站不提供在线编辑或后台管理。这一点由「在 Gitee 上免费搭建个人博客」和站点迁移记录确认。
- Q: 打开「人工智能」这个父分类时，应该看到哪些已发布文章？ → A: 父分类只显示直接归入它的文章；子分类文章只出现在子分类中。
- Q: 同一天发布多篇文章时，首页、上一篇和下一篇应按什么顺序排列？ → A: 同一天内按标题排序，顺序每次访问都相同。
- Q: 归档页按年份列出文章时，每个年份里的文章应按什么顺序排列？ → A: 年份内按发布日期从旧到新排列。同一天内仍按标题排序，顺序每次访问都相同。
- Q: 分类页和标签页里的文章，应按什么顺序排列？ → A: 按发布日期从新到旧排列。同一天内按标题排序，顺序每次访问都相同。
- Q: 搜索结果应按什么顺序排列？ → A: 匹配的文章按发布日期从新到旧排列，同一天按标题排序，顺序每次访问都相同。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 首页文章流 (Priority: P1)

访客打开首页，看到这位作者最新的已发布文章。每篇文章展示标题、摘要、分类和标签，访客可以从其中一篇进入正文。

**Why this priority**: 首页是读者进入博客的第一站。没有文章流，其余阅读、归档和发现能力都没有入口。

**Independent Test**: 准备若干篇已发布文章，其中至少两篇发布日期相同。打开首页，确认只出现已发布文章、按最新在前排列，同一天内按标题排序，且每篇都能看到标题、摘要、分类和标签并进入正文。

**Acceptance Scenarios**:

1. **Given** 站点已有多篇已发布文章，其中两篇发布日期相同，**When** 访客打开首页，**Then** 看到按最新在前排列的文章流；同一天的文章按标题排序，每次访问顺序相同。每篇都有标题、摘要、分类和标签。
2. **Given** 首页文章流中的一篇文章，**When** 访客选择进入正文，**Then** 打开该篇文章的阅读页，而不是分类页、标签页或搜索结果。
3. **Given** 一篇文章尚未发布，**When** 访客打开首页，**Then** 该文章不出现在文章流中。
4. **Given** 当前没有已发布文章，**When** 访客打开首页，**Then** 看到暂时没有文章，而不是错误页。

---

### User Story 2 - 文章阅读 (Priority: P1)

访客阅读一篇已发布文章时，能看到标题、发布日期、字数、预计阅读时间、正文和正文目录，并能前往上一篇和下一篇。

**Why this priority**: 正文是博客对读者的核心价值，与首页文章流同为最小可用阅读体验。

**Independent Test**: 打开一篇有多级标题的已发布文章，核对阅读信息与正文目录，再分别前往上一篇和下一篇，确认顺序与文章流一致。

**Acceptance Scenarios**:

1. **Given** 一篇已发布文章，**When** 访客打开正文页，**Then** 看到标题、发布日期、字数、预计阅读时间和正文。
2. **Given** 正文包含可列入目录的标题，**When** 访客查看正文目录并选择其中一项，**Then** 能定位到正文中对应的部分。
3. **Given** 当前文章在最新文章顺序中既有更新的一篇也有更旧的一篇，**When** 访客查看文末导航，**Then** 可以前往上一篇和下一篇，且两篇都是已发布文章。
4. **Given** 当前文章是最新或最旧的已发布文章，**When** 访客查看文末导航，**Then** 缺少的一侧不提供无效链接。
5. **Given** 一篇文章已不再发布，**When** 访客访问它原来的正文地址，**Then** 被告知文章不存在，看不到正文。

---

### User Story 3 - 归档 (Priority: P2)

访客按年份集中查看全部已发布文章。归档页显示文章总数，并在文章较多时分页浏览。

**Why this priority**: 归档让读者按时间回看全部文章，但不阻塞首页和单篇阅读。

**Independent Test**: 准备跨多个年份、合计 45 篇已发布文章，同一年内至少有两篇日期不同、两篇日期相同。打开归档页，确认总数为 45、按年份分组、年份内从旧到新，并且可以分页看完每一篇。

**Acceptance Scenarios**:

1. **Given** 已发布文章分布在多个年份，**When** 访客打开归档，**Then** 文章按年份集中列出。每个年份内按发布日期从旧到新排列；同一天的文章按标题排序。
2. **Given** 全站共有 45 篇已发布文章，**When** 访客打开归档，**Then** 页面显示共有 45 篇。
3. **Given** 已发布文章数量超过一页，**When** 访客使用分页，**Then** 可以浏览其余文章，且不会重复或漏掉已发布文章。
4. **Given** 一篇文章尚未发布，**When** 访客浏览任意归档页，**Then** 该文章不计入总数，也不出现在列表中。

---

### User Story 4 - 分类 (Priority: P2)

访客用层级分类浏览文章，例如「人工智能 / 深度学习」。分类页显示每个分类下的文章数量，访客可以进入某一分类查看其中的已发布文章。

**Why this priority**: 分类是按主题浏览的主要结构，比标签更稳定，但仍依赖已有文章。

**Independent Test**: 准备父分类「人工智能」及其子分类「深度学习」，分别放入数量已知的已发布文章，打开分类页核对每级数量，再进入子分类确认只看到该分类的文章。

**Acceptance Scenarios**:

1. **Given** 文章使用了父子分类，**When** 访客打开分类页，**Then** 能看到层级关系，例如「人工智能 / 深度学习」，以及每个分类下的已发布文章数量。
2. **Given** 访客选择一个分类，**When** 分类页列出文章，**Then** 只列出已发布且直接归入该分类的文章，按发布日期从新到旧排列，同一天按标题排序，每篇可进入正文。
3. **Given** 「深度学习」是「人工智能」的子分类，且文章直接归入「深度学习」，**When** 访客打开「人工智能」，**Then** 看不到这些文章；打开「深度学习」时才能看到。它们只计入「深度学习」的数量。
4. **Given** 一篇文章同时填写了分类和多个标签，**When** 访客查看该文章，**Then** 它只属于一个分类，标签不改变它的分类归属。
5. **Given** 一个分类下没有直接归入的已发布文章，**When** 访客打开该分类，**Then** 看到该分类暂时没有文章，数量显示为 0。子分类另有文章时，父分类数量仍为 0。

---

### User Story 5 - 标签 (Priority: P2)

访客用比分类更细的关键词查找文章。一篇文章可以有多个标签，访客可以从文章进入某个标签，看到使用该标签的已发布文章。

**Why this priority**: 标签补充分类无法表达的交叉主题，但不是首页阅读的前提。

**Independent Test**: 准备一篇同时带有两个标签的已发布文章，从文章进入每个标签页，确认两个标签页都能找到这篇文章，且文章仍只显示一个分类。

**Acceptance Scenarios**:

1. **Given** 一篇已发布文章有多个标签，**When** 访客在首页或正文查看它，**Then** 能看到全部标签，并且只看到一个分类。
2. **Given** 访客选择一个标签，**When** 打开该标签页，**Then** 看到使用这个标签的已发布文章，按发布日期从新到旧排列，同一天按标题排序，每篇可进入正文。
3. **Given** 同一篇文章使用了两个标签，**When** 访客分别打开这两个标签页，**Then** 两个页面都能找到这篇文章。
4. **Given** 一个标签没有被任何已发布文章使用，**When** 访客打开标签列表，**Then** 该标签不作为可浏览入口出现。

---

### User Story 6 - 站内搜索 (Priority: P2)

访客在全站使用关键词搜索，只在已发布文章中查找内容，并从结果进入正文。

**Why this priority**: 搜索是已知关键词时的直接查找方式，可与分类、标签和归档独立使用。

**Independent Test**: 用一篇已发布文章中的标题词、摘要词和正文词分别搜索，再用一篇未发布文章中的独有词语搜索，确认只有已发布文章出现。

**Acceptance Scenarios**:

1. **Given** 访客位于站点任意主要页面，**When** 查看页面，**Then** 能找到全站关键词搜索入口。
2. **Given** 关键词出现在多篇已发布文章的标题、摘要或正文中，**When** 访客搜索该关键词，**Then** 这些文章按发布日期从新到旧出现，同一天按标题排序，每篇可进入正文。
3. **Given** 关键词只出现在未发布文章中，**When** 访客搜索该关键词，**Then** 该文章不出现在结果中。
4. **Given** 没有已发布文章匹配关键词，**When** 访客搜索，**Then** 看到没有找到相关文章，而不是错误页。

---

### User Story 7 - 关于与历史 (Priority: P3)

访客可以阅读作者介绍，也可以查看一条独立的博客时间线。历史记录博客本身发生过的事情，不是按年份列出的文章归档。

**Why this priority**: 关于与历史帮助读者理解作者和站点，但不影响找文章和读文章。

**Independent Test**: 分别打开关于页和历史页，确认关于页是作者介绍、历史页按时间列出博客事件；再打开归档页，确认历史事件不出现在归档文章列表中。

**Acceptance Scenarios**:

1. **Given** 作者已经写好介绍，**When** 访客打开关于页，**Then** 看到作者介绍，而不是文章列表。
2. **Given** 博客时间线已有事件，**When** 访客打开历史页，**Then** 看到按时间排列的博客事件。
3. **Given** 历史页和归档页都可访问，**When** 访客比较两者，**Then** 历史页不是文章归档，归档页也不展示历史事件。
4. **Given** 访客在历史页看到一条与某篇已发布文章相关的事件，**When** 该事件提供文章入口，**Then** 可以进入对应正文；没有入口的事件仍只作为时间线事件展示。

---

### Edge Cases

- 文章尚未发布：不出现在首页、归档、分类、标签、搜索和上一篇/下一篇中，也不计入归档总数或分类文章数量。
- 已发布文章缺少摘要：仍可进入正文；文章流中的摘要位置说明暂无摘要，不把正文全文塞进摘要位置。
- 已发布文章没有可列入目录的标题：正文页不显示空目录，其余阅读信息照常显示。
- 字数为 0 或正文为空：不作为可发布文章展示。
- 预计阅读时间不足 1 分钟：显示为 1 分钟，不显示 0 分钟。
- 归档总数不是 45：页面显示实际已发布文章总数。45 是验收样例，不是固定容量。
- 归档只有一页：仍显示总数，不显示无法使用的分页。
- 分类只有一级：按一级分类展示并显示数量，不强制制造空的父分类。
- 父分类与子分类：文章只出现在它直接归入的那一级。父分类的文章数量不包含子分类文章，也不等于子分类数量之和。
- 一篇文章被填入多个分类：不发布该篇，并在作者核对发布结果时指出它只能属于一个分类。
- 标签与分类同名：仍分别作为标签和分类展示，互不合并。
- 搜索关键词为空或只有空白：不执行搜索，提示访客输入关键词。
- 搜索大小写或首尾空格不同：仍能找到对应的已发布文章。
- 关于页尚无介绍，或历史页尚无事件：各自显示暂时没有内容，不影响文章阅读。
- 历史事件指向的文章后来不再发布：历史页保留事件，但不再提供该文章入口。

## Requirements *(mandatory)*

### Functional Requirements

**内容发布**

- **FR-001**: 文章 MUST 由作者在本地写作，生成静态站点后发布。
- **FR-002**: 网站 MUST NOT 提供在线编辑或后台管理，也 MUST NOT 提供替代本地写作和发布的上传入口。
- **FR-003**: 网站 MUST 只展示已发布文章。未发布文章 MUST NOT 出现在首页、阅读页、归档、分类、标签、搜索或上一篇/下一篇中。

**首页文章流**

- **FR-004**: 首页 MUST 展示最新已发布文章组成的文章流，最新的排在前面。发布日期相同的文章 MUST 按标题排序，且每次访问顺序相同。
- **FR-005**: 文章流中的每篇文章 MUST 展示标题、摘要、一个分类和它的全部标签。
- **FR-006**: 访客 MUST 能从文章流中的一篇文章进入它的正文页。

**文章阅读**

- **FR-007**: 正文页 MUST 展示标题、发布日期、字数、预计阅读时间和正文。
- **FR-008**: 正文包含可定位的标题时，正文页 MUST 提供正文目录，访客选择目录项后 MUST 能到达对应部分。
- **FR-009**: 正文页 MUST 提供上一篇和下一篇。两者都 MUST 是已发布文章，并遵循与首页相同的顺序：先按发布日期从新到旧，同一天再按标题排序。
- **FR-010**: 当前文章是最新或最旧的已发布文章时，系统 MUST NOT 为缺少的一侧提供无效链接。
- **FR-011**: 已不再发布的文章地址 MUST 表现为不存在，且 MUST NOT 继续显示正文。

**归档**

- **FR-012**: 归档 MUST 按年份集中列出全部已发布文章。每个年份内 MUST 按发布日期从旧到新排列；同一天 MUST 按标题排序，且每次访问顺序相同。
- **FR-013**: 归档页 MUST 显示已发布文章总数。当已发布文章为 45 篇时，页面 MUST 显示共有 45 篇。
- **FR-014**: 归档文章超过一页时，系统 MUST 提供分页，使访客能看完全部已发布文章且不重复、不遗漏。

**分类与标签**

- **FR-015**: 系统 MUST 用层级分类组织文章，并 MUST 能表达「人工智能 / 深度学习」这样的父子分类。
- **FR-016**: 分类页 MUST 显示每个分类直接归入的已发布文章数量。访客 MUST 能进入一个分类，且只看到直接归入该分类的已发布文章。这些文章 MUST 按发布日期从新到旧排列，同一天 MUST 按标题排序。父分类 MUST NOT 列出或计量子分类的文章。
- **FR-017**: 系统 MUST 用标签组织比分类更细的关键词。访客 MUST 能从标签查看使用该标签的已发布文章，并按发布日期从新到旧排列，同一天按标题排序。
- **FR-018**: 一篇已发布文章 MUST 同时属于一个分类和零个或多个标签。系统 MUST NOT 让一篇文章属于多个分类。

**站内搜索**

- **FR-019**: 全站 MUST 提供关键词搜索入口。
- **FR-020**: 搜索 MUST 只在已发布文章中查找，并 MUST 能匹配标题、摘要和正文。
- **FR-021**: 搜索结果 MUST 按发布日期从新到旧排列，同一天 MUST 按标题排序，且每次访问顺序相同。访客 MUST 能从结果进入对应文章正文。没有匹配时，系统 MUST 明确说明没有找到相关文章。

**关于与历史**

- **FR-022**: 关于页 MUST 展示作者介绍，MUST NOT 用文章列表代替作者介绍。
- **FR-023**: 历史页 MUST 展示一条独立的博客时间线。历史 MUST NOT 作为文章归档的另一种排列。
- **FR-024**: 归档页 MUST NOT 展示历史事件。历史事件指向的文章不再发布后，历史页 MUST 保留事件并移除文章入口。

### Key Entities

- **文章 (Article)**: 作者在本地写成并发布到站点的一篇文章。包含标题、摘要、正文、一个分类、多个标签、发布日期、字数和预计阅读时间。只有已发布文章对访客可见。
- **分类 (Category)**: 组织文章的层级主题，例如「人工智能」及其子分类「深度学习」。一个分类知道自己的父分类，以及直接归入自己的已发布文章数量。这个数量不包含子分类的文章。
- **标签 (Tag)**: 比分类更细的关键词。一篇文章可以有多个标签，一个标签可以被多篇文章使用。
- **正文目录 (Table of Contents)**: 从一篇文章的正文标题得到的阅读导航，只服务于该篇文章。
- **归档 (Archive)**: 按年份集中展示全部已发布文章的集合，包含文章总数和分页。年份内从旧到新排列，同一天按标题排序。
- **搜索结果 (Search Result)**: 访客用关键词在已发布文章中找到的文章集合。结果按发布日期从新到旧排列，同一天按标题排序。
- **关于 (About)**: 作者介绍，不是文章。
- **历史事件 (History Event)**: 博客时间线上的一件事。它不是归档中的文章；可以提及某篇文章，但不因此变成文章列表项。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 90% 的首次访客可以在 1 分钟内从首页进入一篇文章正文，且不需要先理解分类、标签或归档。
- **SC-002**: 在包含标题、摘要、分类和标签的首页抽查中，缺失其中任一项的已发布文章数为 0。
- **SC-003**: 访客打开任意已发布正文后，都能核对标题、发布日期、字数和预计阅读时间；有目录的文章都能从目录到达对应部分。
- **SC-004**: 对 45 篇跨年份文章的归档验收中，页面显示共有 45 篇，分页可以覆盖全部 45 篇，重复或遗漏为 0。
- **SC-005**: 分类页显示的每个分类文章数量与直接归入该分类、且能从该分类打开的已发布文章数一致，抽查不一致次数为 0。父分类数量不等于子分类数量之和时，不算失败。
- **SC-006**: 一篇带有一个分类和多个标签的文章，在分类页只出现一次，在每个对应标签页都能找到。
- **SC-007**: 95% 的关键词搜索在 1 秒内给出结果；未发布文章出现在结果中的次数为 0。
- **SC-008**: 访客可以区分关于、历史和归档：关于是作者介绍，历史是博客时间线，归档是按年份列出的文章。三者互相替代的次数为 0。

## Assumptions

- 本期只展示这一位作者的个人博客，不展示其他作者的文章。
- 作者使用自己的 Gitee 仓库保存本地写作内容。网站只展示已经发布的站点内容，不接收仓库的上传或下载。
- 「在 Gitee 上免费搭建个人博客」和站点迁移记录足以确认发布方式：本地写作，生成站点后发布。网站不提供在线编辑或后台管理。
- 文章的写作文件格式、目录和标题提取方式不在本期读者需求中定义。访客只感知已发布文章的标题、摘要、分类、标签和正文。
- 摘要由作者随文章提供。未提供时，文章流明确显示暂无摘要，不自动截取正文冒充摘要。
- 字数按正文可阅读文字计数。预计阅读时间按每分钟 400 字计算，不足 1 分钟按 1 分钟显示。
- 一篇文章只能有一个分类，并且只直接归入这一级分类。父分类不继承子分类的文章。分类可以用「父分类 / 子分类」表示层级。标签可以有多个，数量不设上限，但每个标签都应是短关键词。
- 归档中的 45 篇是验收样例。实际总数随已发布文章变化，分页大小以保证能看完为准，默认每页 10 篇。
- 上一篇指首页顺序中更靠前的一篇，下一篇指更靠后的一篇。首页、分类页、标签页和搜索结果都按发布日期从新到旧排列，同一天按标题排序。归档年份内从旧到新，同一天仍按标题排序。这些顺序每次访问都相同。标题排序按读者看到的标题文本比较。
- 搜索匹配标题、摘要和正文，不匹配分类名、标签名、关于页或历史事件。分类和标签通过各自的页面浏览。
- 关于内容由作者在本地写好后随站点发布。历史事件由作者随站点发布，不从文章列表自动生成。
- 本期不做评论、点赞、多作者、在线编辑、后台管理和访客账号。
