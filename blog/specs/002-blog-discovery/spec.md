# Feature Specification: 来都来了的博客浏览

**Feature Branch**: `002-blog-discovery`

**Created**: 2026-10-14

**Status**: Draft

**Input**: User description: "优化现有的个人博客「来都来了」，让读者能像浏览一个完整博客站那样找到和阅读文章。站点仍然只有一位作者，文章继续由作者在本地写成 Markdown，再用 Git 上传到自己的 Gitee 仓库；网站只展示，不提供在线写作、编辑或后台。首页展示最新文章，每篇至少显示标题、一段摘要、发布日期、所属分类和标签，并能进入正文。正文页显示标题、发布日期、字数、预计阅读时间、正文目录，以及上一篇和下一篇。增加按年份浏览全部文章的归档，并分页。增加分类和标签：一篇文章属于一个分类，分类可以有上下级；一篇文章可以有多个标签。分类页和标签页都显示包含的文章及数量。增加站内关键词搜索，只搜索已展示的文章。增加「关于」页，用来介绍作者；增加「历史」页，用来记录博客本身的重要节点，它不是文章归档。现有的文章列表和正文阅读继续可用。本期不做评论、点赞、在线编辑和多作者。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从首页进入文章 (Priority: P1)

读者打开「来都来了」，在首页看到最新文章的标题、摘要、发布日期、分类和标签，并进入正文阅读。

**Why this priority**: 这是读者进入站点后的第一条路径。没有它，分类、标签、归档和搜索都没有可到达的阅读结果。

**Independent Test**: 准备三篇已展示文章，打开首页，确认按发布时间从新到旧显示摘要和归属信息；点击一篇进入正文，确认正文内容与该文章一致。

**Acceptance Scenarios**:

1. **Given** 站点已有多篇已展示文章，**When** 读者打开首页，**Then** 文章按发布日期从新到旧排列，每篇显示标题、摘要、发布日期、分类和标签。
2. **Given** 首页的一篇文章，**When** 读者选择它，**Then** 进入该文章正文，而不是另一篇文章。
3. **Given** 一篇文章没有可识别的摘要，**When** 首页展示它，**Then** 使用正文开头的一段文本作为摘要，并标明这是自动摘要。
4. **Given** 站点还没有已展示文章，**When** 读者打开首页，**Then** 看到暂时没有文章，而不是空白或错误。

---

### User Story 2 - 阅读正文并继续阅读 (Priority: P2)

读者在正文页看到文章信息、目录、上一篇和下一篇，并可以继续阅读相邻文章。

**Why this priority**: 首页只负责发现文章。正文页决定读者能否理解文章结构并顺着时间继续阅读。

**Independent Test**: 打开一篇有三个标题的文章，确认目录包含这三个标题；从中间一篇进入上一篇和下一篇，确认顺序按发布日期排列。

**Acceptance Scenarios**:

1. **Given** 一篇已展示文章，**When** 读者打开正文，**Then** 看到标题、发布日期、字数、预计阅读时间和正文。
2. **Given** 正文包含章节标题，**When** 读者查看目录，**Then** 目录列出这些标题，选择后到达对应章节。
3. **Given** 一篇不是最新也不是最早的文章，**When** 读者选择上一篇或下一篇，**Then** 按发布日期进入相邻文章。
4. **Given** 最新或最早的一篇文章，**When** 读者查看相邻文章入口，**Then** 不存在的一侧不显示可点击入口。

---

### User Story 3 - 按归档、分类和标签找到文章 (Priority: P3)

读者通过年份归档、层级分类和标签找到同一组文章，并看到每个分组包含多少篇。

**Why this priority**: 这是从「最新文章列表」变成可浏览博客站的主要能力。它依赖文章已经可以阅读，所以排在前两个故事之后。

**Independent Test**: 准备跨两个年份、两个层级分类和两个标签的文章，分别从归档、分类和标签进入，确认文章集合、数量和链接一致。

**Acceptance Scenarios**:

1. **Given** 多篇不同年份的文章，**When** 读者打开归档，**Then** 文章按年份分组，并可以分页浏览全部文章。
2. **Given** 一个有上级和下级的分类，**When** 读者打开分类页，**Then** 能看到层级、每个分类的文章数量，以及该分类直接包含的文章。
3. **Given** 一个标签下有多篇文章，**When** 读者打开该标签，**Then** 看到这些文章和文章数量。
4. **Given** 一篇文章所属分类或标签，**When** 读者从正文页选择它，**Then** 进入对应的分类页或标签页。

---

### User Story 4 - 搜索已展示文章 (Priority: P4)

读者输入关键词，只在已展示文章中查找标题、摘要和正文，并进入匹配的文章。

**Why this priority**: 搜索是跨分类和标签的查找方式。它依赖已展示内容，但不影响按目录浏览，所以排在后面。

**Independent Test**: 用一个只出现在某篇正文中的词搜索，确认该文章出现；用一个只存在于未展示文件中的词搜索，确认没有结果。

**Acceptance Scenarios**:

1. **Given** 关键词出现在文章标题、摘要或正文中，**When** 读者搜索，**Then** 结果包含该文章，并显示匹配位置的简短片段。
2. **Given** 关键词不在任何已展示文章中，**When** 读者搜索，**Then** 显示没有匹配结果，而不是错误。
3. **Given** 一个未展示或被拒绝的仓库文件包含关键词，**When** 读者搜索，**Then** 结果不包含该文件。

---

### User Story 5 - 阅读关于和历史 (Priority: P5)

读者打开「关于」了解作者，打开「历史」按时间查看博客本身的重要节点。

**Why this priority**: 这两页完善站点身份，但不影响找文章和读文章，所以优先级最低。

**Independent Test**: 分别准备关于介绍和两条历史节点，打开两个页面，确认内容、顺序和用途没有与文章归档混淆。

**Acceptance Scenarios**:

1. **Given** 作者提供了关于介绍，**When** 读者打开关于页，**Then** 看到该介绍。
2. **Given** 作者提供了多条历史节点，**When** 读者打开历史页，**Then** 节点按日期从新到旧显示。
3. **Given** 历史页的一条节点，**When** 读者查看归档，**Then** 历史节点不作为一篇博客文章出现。

---

### Edge Cases

- 分类名称或标签名称相同但层级位置不同：以完整层级路径区分，不合并。
- 文章声明了不存在的分类或标签：文章仍可阅读，缺失的归属在页面上标明未识别，不导致整站失败。
- 同一篇文章被放入多个分类：只采用声明中的第一个分类，并在读取结果中说明被忽略的分类。
- 文章没有章节标题：正文页不显示空目录。
- 字数按正文可见文字计数，不把标记符号单独作为有效阅读文字。预计阅读时间按每分钟 300 字计算，不足 1 分钟显示为 1 分钟。
- 搜索只输入空格：不执行搜索，并提示输入关键词。
- 搜索结果很多：分页显示，不一次加载全部结果。
- 关于或历史内容缺失：对应页面说明内容尚未编写，不影响文章浏览。

## Requirements *(mandatory)*

### Functional Requirements

**首页与正文**

- **FR-001**: 首页 MUST 按发布日期从新到旧展示已发布文章，每篇 MUST 显示标题、摘要、发布日期、分类和标签，并 MUST 能进入正文。
- **FR-002**: 文章未提供摘要时，系统 MUST 使用正文开头不超过 120 个字符的文本作为摘要，并 MUST 向读者标明这是自动摘要。
- **FR-003**: 正文页 MUST 显示标题、发布日期、正文字数、预计阅读时间、正文和章节目录。没有章节时 MUST NOT 显示空目录。
- **FR-004**: 正文页 MUST 提供按发布日期确定的上一篇和下一篇。不存在相邻文章时 MUST NOT 显示无效入口。

**归档、分类和标签**

- **FR-005**: 系统 MUST 提供按年份分组的归档，并 MUST 支持分页浏览全部文章。
- **FR-006**: 一篇文章 MUST 只属于一个分类。分类 MUST 支持上级和下级。分类页 MUST 显示层级、文章数量和文章列表。
- **FR-007**: 一篇文章 MUST 可以有零个、一个或多个标签。标签页 MUST 显示文章数量和文章列表。
- **FR-008**: 读者 MUST 能从正文页进入该文章的分类页和标签页。

**搜索与站点页**

- **FR-009**: 系统 MUST 允许读者按关键词搜索已展示文章的标题、摘要和正文，并显示匹配片段。
- **FR-010**: 搜索 MUST NOT 返回未展示或被拒绝的仓库文件。空关键词 MUST NOT 执行搜索。
- **FR-011**: 系统 MUST 提供关于页和历史页。历史页按日期从新到旧展示博客节点，这些节点 MUST NOT 出现在文章归档中。

**内容边界**

- **FR-012**: 站点 MUST 继续只展示这一位作者通过 Gitee 仓库提交的内容。网站 MUST NOT 提供在线写作、编辑、评论、点赞或多作者能力。
- **FR-013**: 分类、标签、摘要、关于介绍和历史节点 MUST 来自作者提交到仓库的内容，不由网站另行创建。

### Key Entities

- **文章 (Article)**: 现有已展示博客。新增摘要、发布日期、字数、预计阅读时间、分类、标签和章节标题。
- **分类 (Category)**: 文章的唯一归属，可有一个上级分类。
- **标签 (Tag)**: 可被多篇文章共用的关键词。一篇文章可关联多个标签。
- **历史节点 (History Entry)**: 博客自身的日期和说明。它不是文章。
- **关于介绍 (About Profile)**: 作者提供的一段站点介绍。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 读者从打开首页到进入一篇文章正文不超过 2 次选择。
- **SC-002**: 在 20 篇测试文章中，首页、归档、分类、标签和搜索到达的文章与预期集合不一致的次数为 0。
- **SC-003**: 正文页显示的上一篇和下一篇顺序错误次数为 0。
- **SC-004**: 搜索结果包含未展示仓库文件的次数为 0。
- **SC-005**: 读者可以在不查看说明的情况下，从首页找到归档、分类、标签、搜索、关于和历史入口。

## Assumptions

- 现有「来都来了」站点、Gitee 仓库读取和文章正文展示继续有效。本期只增加发现和阅读信息。
- 发布日期优先取文章声明的日期；没有声明时，使用仓库中的更新时间，并在规划阶段记录展示名称。
- 分类、标签和摘要由文章开头的声明信息提供。具体写法留到规划阶段，但必须能表达一个分类、多个标签和可选摘要。
- 分类层级最多支持三级。超过三级时，文章仍可阅读，超出的层级在读取结果中说明。
- 关于介绍和历史节点分别来自仓库中的独立内容文件。文件路径留到规划阶段确定。
- 字数按正文可见文字计数，阅读时间按每分钟 300 字估算。
- 本期不做评论、点赞、分享统计、在线编辑、多作者和管理后台。
